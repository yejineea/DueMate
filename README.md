# 🍅 DueMate

할 일이 많은 대학생 대신 **"지금 무엇부터 할지"를 정해 주고, 바로 집중하게 해 주는** 과제·일정 관리 웹 앱입니다.

| 바로가기 | 주소 |
| --- | --- |
| 웹사이트 (내 데이터로 사용) | https://yejineea.github.io/DueMate/ |
| 샘플 데이터로 체험 (저장 안 됨) | https://yejineea.github.io/DueMate/?demo |
| 브라우저 테스트 (138건) | https://yejineea.github.io/DueMate/tests.html |

## 실행 방법

- **브라우저만 있으면 됩니다.** 설치, 회원가입, 서버가 필요 없습니다. 위 웹사이트 주소로 들어가거나, 저장소를 내려받아 `index.html`을 더블클릭하세요.
- 처음이라면 `?demo` 주소로 샘플 화면부터 둘러보세요. 데모 모드에서 바꾼 내용은 저장되지 않습니다.
- 데이터는 이 브라우저의 `localStorage`에만 저장됩니다. 다른 기기에서 쓰려면 **설정 → JSON 백업** 파일을 그 기기에서 **JSON 복원**으로 불러오세요.
- 휴대폰에서도 같은 주소로 쓸 수 있습니다. 화면이 좁으면 탭이 아래쪽 바로 바뀝니다.

### 처음 5분 사용법

1. **설정 → 일정**에 수업과 알바를 `매주 반복`으로 넣습니다. 공부 가능 시간이 자동으로 계산됩니다.
2. 오른쪽 위 **+ 과제 추가**에서 과목·유형·제목·마감만 넣습니다. 예상 시간은 자동으로 채워집니다.
3. **뽀모도로 탭** 가운데에 지금 할 과제가 뜹니다. 큰 원 안의 **▶ 시작**을 누르면 25분 집중이 시작됩니다.
4. 집중이 끝나면 "이 단계 끝냈나요?"에 답합니다. 과제를 다 하면 **완료 처리**를 누릅니다.
5. **토마토 키우기 탭**에서 이번 주에 모은 🍅만큼 토마토가 자란 모습을 확인합니다.

## 1. 제작한 것 소개

### 1-1. 왜 만들었나

시험 기간에는 여러 과목의 과제와 시험이 한꺼번에 몰립니다. 할 일이 많을수록 "무엇부터 할지" 고민하는 데에도 시간과 에너지가 듭니다. DueMate는 **마감까지 남은 시간**, **남은 작업량**, 그리고 **수업·알바를 빼고 실제로 쓸 수 있는 공부 시간**을 함께 계산해서 지금 할 일 하나를 골라 줍니다. 그다음 뽀모도로로 바로 시작하게 합니다.

10월에 만든 v1을 직접 써 보니 아쉬운 점이 있었고, 11월에 v2로 크게 고쳤습니다.

| v1에서 아쉬웠던 점 | v2에서 바꾼 것 |
| --- | --- |
| 첫 화면에 통계·차트·목록이 섞여 **지금 할 일이 눈에 안 띔** | 첫 화면 = **뽀모도로 탭**: 지금 할 일 + 큰 타이머 + 오늘 계획만 |
| 요일별 공부 가능 시간을 **직접 어림잡아 입력** | 일정만 넣으면 **자동 계산** (원하면 직접 입력도 가능) |
| 과제마다 예상 소요 시간을 **직접 입력** (기본 3시간 일괄) | 유형·난이도로 **자동 추정**, 실제 걸린 시간으로 **보정** |
| 추천을 봐도 **바로 시작할 장치가 약함** (스톱워치) | 과제별 **뽀모도로 타이머**, 집중 시간 자동 기록 |
| 계속 쓰게 만드는 **동기 부여가 없음** | 모은 🍅로 **토마토 키우기**와 배지 |

| v1 첫 화면 (대시보드) | v2 첫 화면 (뽀모도로 탭) |
| --- | --- |

### 1-2. 탭 구성

| 탭 | 한 줄 설명 |
| --- | --- |
| 🍅 **뽀모도로** (첫 화면) | 지금 할 일을 옆으로 넘기며 고르고, 과제별 타이머로 집중. 오른쪽에 오늘 계획 |
| **To Do** | 과제 목록과 캘린더. 과제 추가·수정, 단계(하위 작업), 작업 기록 |
| **리포트** | 앞으로 7일·4주 작업량, 학습 시간, 예상 정확도와 보정, 성적과 목표 점수 |
| **토마토 키우기** | 이번 주 🍅만큼 자라는 토마토, 주간 목표, 배지 (재미 요소) |
| **설정** | 공부 가능 시간(자동/직접), 일정, 알림, 테마, 과목, 백업 |

### 1-3. 탭별 화면과 사용법

#### 🍅 뽀모도로 탭

![뽀모도로 탭](docs/images/v2-pomodoro.png)

**왼쪽: 지금 할 일 + 타이머**
- 맨 처음 보이는 과제가 **지금 할 일**입니다. 오늘 계획의 첫 번째 칸과 같은 과제입니다.
- 과제는 **옆으로 밀거나**, `‹ ›` 버튼, 아래 점, 키보드 `← →`로 바꿉니다. 순서는 오늘 계획 순서 다음 우선순위 순서입니다.
- 위쪽 태그가 추천 이유입니다. 예: `8시간 남음` `시간 부족 3.0h/2.7h` `중요도 높음` + 판정 `우선 처리` / `오늘 시작` / `여유 있음`
- **큰 원 = 타이머**: 빨강은 집중, 연두는 휴식입니다. 시작·일시정지·재개·중지 버튼이 원 안에 있습니다.
- **바깥 얇은 연두 링**은 이 과제의 `기록 시간 ÷ 예상 시간` 진행률입니다.
- **타이머는 과제마다 따로** 돕니다. 다른 과제를 시작하면 지금 타이머는 남은 시간 그대로 멈춰 두었다가, 돌아와서 이어서 할 수 있습니다.
- 아래쪽 `단계 1/4 · 다음 단계 주제 정하기 [✓ 끝냄]`에서 단계를 체크합니다. 🍅 하나를 마치면 "이 단계 끝냈나요?"를 물어봅니다.
- 다른 탭에 있으면 위쪽에 `🍅 12:58 집중` 칩만 보이고, 누르면 이 탭으로 돌아옵니다.

**오른쪽: 오늘 계획**
- 오늘 남은 공부 가능 시간을 🍅(25분 집중 + 5분 휴식) 단위로 나눠 `15:20–17:55 영어 에세이 🍅×5`처럼 **실제 시각에 배치**합니다.
- **자동이 기본이고, 직접 고칠 수 있습니다.**
  - `− / +`로 개수, `▲ ▼`로 순서, `✕`로 오늘 제외, "+ 오늘 계획에 과제 추가"로 다른 과제를 넣습니다.
  - 개수를 바꾼 과제는 고정되고, 나머지 과제는 남는 시간에 맞춰 자동으로 다시 배정됩니다.
  - 고친 내용은 **오늘 하루만** 유지됩니다. "자동으로 되돌리기"로 언제든 원래대로 돌아갑니다.
- 아래에는 핵심 경고(`임박` `마감 지남` `시간 부족`), 7일 내 마감, 뽀모도로 설정(집중·휴식 길이, 알림음)이 있습니다.

#### To Do 탭

![To Do 탭](docs/images/v2-todo.png)

- 기본으로 **미완료 과제를 추천 순서대로** 보여 줍니다. 과목·상태·정렬 필터가 있습니다.
- 카드에는 마감, 남은 시간, 진행률, `기록 / 예상` 시간, 🍅 개수가 표시됩니다.
- **🍅 시작**을 누르면 뽀모도로 탭으로 이동해 바로 집중을 시작합니다.
- 제목을 누르면 상세가 펼쳐집니다.
  - **단계(하위 작업)**를 추가·체크·수정·삭제합니다. 모든 단계를 체크하면 과제가 자동으로 완료됩니다.
  - **작업 기록**에서 `+15분` `+30분` `+1시간`으로 타이머 없이 한 시간을 직접 더할 수 있습니다.
- **완료 처리** 직후 아래 알림의 **되돌리기**로 6초 안에 취소할 수 있습니다.

**과제 추가 화면**: 입력이 꼭 필요한 칸은 과목·유형·제목·마감뿐입니다.

![과제 추가](docs/images/v2-form.png)

- **예상 소요 시간은 자동으로 채워집니다.** 아래에 계산 근거가 보입니다. 예: `보고서 기본 3h · 난이도 3 ×1 · 내 기록 보정 ×1.13 (완료 3건) → 3.5h`
- 숫자를 직접 고치면 자동 계산이 꺼지고 그 값이 유지됩니다.
- **반복**에서 `매주` / `매월`을 고르면, 완료할 때 다음 회차가 자동으로 생깁니다. 마감은 1주 또는 1달 뒤이고, 단계는 초기화됩니다.
- 하위 작업·설명·메모는 "더보기"에 접혀 있습니다. 유형별 템플릿으로 단계를 한 번에 채울 수 있습니다.

**캘린더**: To Do 탭 위쪽 `목록 | 캘린더`로 전환합니다. 월간·주간 보기를 지원하고, 시험은 빨강, 하루·매월 일정은 회색, 같은 날 마감이 2개 이상이면 `겹침`으로 표시됩니다.

![캘린더](docs/images/v2-calendar.png)

#### 리포트 탭

![리포트 탭](docs/images/v2-report.png)

- **위쪽 카드**: 완료율, 이번 주 집중 시간, 미제출, **예상 정확도**(실제 ÷ 예상)
- **앞으로 7일 작업량 vs 공부 가능 시간**: 그날 마감인 작업량 막대입니다. 마감 전까지 시간이 모자라면 빨강으로 표시됩니다.
- **향후 4주 작업량**, **최근 14일 학습 시간**, **과목별 완료**
- **완료한 과제의 예상 vs 실제**와 **내 예상 보정**: 유형별 보정값(예: `코딩 ×1.13 (4건)`), 유형별 `초기화`, `보정 사용` 끄기

위쪽 `통계 | 성적`으로 성적 화면으로 전환합니다.

![성적](docs/images/v2-grades.png)

- 평가 항목별 반영 비율·만점·점수를 넣으면 확보 점수와 현재 성적을 계산합니다.
- **목표 점수**를 넣으면 `남은 항목(60%)에서 평균 87% 필요`처럼 남은 시험에서 받아야 할 점수를 알려 줍니다.

#### 토마토 키우기 탭

![토마토 키우기 탭](docs/images/v2-grow.png)

- **이번 주에 모은 🍅만큼 화분의 토마토가 자랍니다.** 🍅 = 25분 집중을 끝까지 마친 횟수입니다.
- 단계는 주간 목표 대비 비율로 정해지며, 화분 아래에 기준이 표시됩니다.

  | 씨앗 | 새싹 | 줄기 | 꽃봉오리 | 초록 토마토 | 빨간 토마토 |
  | --- | --- | --- | --- | --- | --- |
  | 0개 | 1개~ | 25%~ | 50%~ | 75%~ | 100% |

- 가지에 매달린 토마토가 단계에 따라 **울상에서 활짝 웃는 얼굴**로 바뀌고, 말풍선으로 한마디 합니다. 예: "물 좀 주세요… 🍅 하나만요", "빨갛게 익었어요! 최고예요"
- **주간 목표**(기본 20개)는 그 자리에서 바꿀 수 있습니다. 요일별 🍅, 연속 집중일, 누적 🍅·집중 시간, 주별 그래프도 함께 봅니다.
- **배지 8종**은 동메달 모양입니다. 아직 못 딴 배지는 회색으로 표시되고 `86 / 100`처럼 진행도가 보입니다.

### 1-4. 핵심 기능 자세히

#### ① 우선순위 추천: "지금 할 일" 결정
- **점수** = 마감 임박도(최대 60) + 작업 압박도(최대 30) + 중요도(최대 20) + 난이도(최대 10)
  - 작업 압박도 = 남은 작업 시간 ÷ 마감 전까지 공부 가능 시간
- **남은 작업 시간** = `min(예상 × (1 − 단계 진행률), 예상 − 기록 시간)`. 완료 전에는 예상의 10%를 남깁니다.
- 판정: 70점 이상 `우선 처리`, 45점 이상 `오늘 시작`, 그 밖은 `여유 있음`

#### ② 공부 가능 시간: 자동 계산 / 직접 입력
- **자동 계산(기본)**
  ```
  빈 시간       = 하루 활동 시간(기본 09:00~24:00) − 그날 일정(겹치면 병합)
  공부 가능 시간 = min(하루 최대 공부(기본 8h), 빈 시간 − 식사·이동·휴식(기본 3h))
  ```
  - 공부 가능 시간이 빈 시간 구간에 고르게 퍼져 있다고 보고 계산합니다. 그래서 "지금부터 마감까지" 쓸 수 있는 시간은 남은 빈 시간만큼만 셉니다. 예: 저녁 6시 반이면 오늘은 남은 빈 시간만 셉니다.
  - 종료 시각이 시작보다 이르면(예: 10:00~02:00) 다음 날 새벽까지로 계산합니다.
  - 설정 탭 표에서 요일별 근거(활동·일정·빈 시간·생활·공부 가능)를 볼 수 있고, 최근 14일 실제 평균 학습 시간도 참고로 보여 줍니다.
- **직접 입력**: 요일별 공부 시간을 직접 넣습니다. 이 경우에도 마감 전 가용 시간은 일정을 뺀 빈 시간 구간에 나눠 계산합니다.
- **일정 종류**: 하루만(날짜) / 매주 반복(요일) / 매월 반복(매월 며칠)

#### ③ 뽀모도로
- 집중 25분 → 짧은 휴식 5분 → … → 4회마다 긴 휴식 15분. 길이와 간격은 뽀모도로 탭 아래 설정에서 바꿉니다.
- **과제별 독립 타이머**: 다른 과제를 시작하면 앞 타이머는 남은 시간 그대로 보관되고, 동시에 도는 타이머는 하나뿐입니다.
- 종료 알림음과 브라우저 알림이 있고, 휴식이 끝난 뒤 집중을 자동으로 시작할지 고를 수 있습니다.
- 탭을 닫아 둔 사이 끝난 집중도 기록합니다. 다만 다음 단계는 자동으로 시작하지 않습니다.

#### ④ 예상 소요 시간 자동 추정과 실제 작업 시간 보정
- **추정 공식**
  ```
  예상 시간 = 유형별 기본 시간 × 난이도 계수 × 단계 수 계수 × 내 기록 보정   (0.5시간 단위)
  ```
  | 요소 | 값 |
  | --- | --- |
  | 유형별 기본 시간 | 보고서 3h · 발표 4h · 코딩 5h · 시험 공부 6h · 시험 8h · 기타 2h |
  | 난이도 계수 | 1→×0.6 · 2→×0.8 · 3→×1.0 · 4→×1.3 · 5→×1.6 |
  | 단계 수 계수 | 하위 작업이 보통(유형별 템플릿 개수)보다 많으면 늘리고 적으면 줄임 (×0.7~1.5) |
  | 내 기록 보정 | 완료한 과제의 `실제 ÷ 예상`을 유형별로 평균 (×0.5~2) |
- **실제 작업 시간은 어떻게 재나요?** 과제의 작업 기록을 모두 더한 값이고, 기록은 아래 경우에만 쌓입니다.
  | 상황 | 기록되는 시간 | 🍅 |
  | --- | --- | --- |
  | 25분 집중을 끝까지 마침 | 25분 | +1 |
  | 집중 중에 중지 | 실제로 집중한 시간 (1분 이상일 때) | 그대로 |
  | 과제 상세에서 `+15분` `+30분` `+1시간` | 그만큼 ("직접" 표시, 지울 수 있음) | 그대로 |
  | 완료할 때 "실제로 얼마나 걸렸나요?"에 입력 | 입력한 시간과 기록의 차이만큼 | 그대로 |
  - 휴식 시간은 넣지 않습니다.
  - **기록이 예상의 절반도 안 되는 과제를 완료하면** 실제 걸린 시간을 묻습니다. 타이머 없이 한 작업 때문에 "빨리 끝냈다"로 잘못 보정되는 것을 막기 위해서입니다.
- **보정 방식**
  - 보정에는 완료했고 기록이 있는 과제만 씁니다.
  - 기록이 한두 건일 때 휘둘리지 않도록 1배 쪽으로 당겨서 계산합니다. 같은 기록이 두 번 들어가지 않도록, 각 유형의 기준점은 **다른 유형의 기록**으로 정합니다.
  - 과제를 완료할 때마다 보정값이 다시 계산되고, 진행 중인 "자동 계산" 과제의 예상 시간도 바로 갱신됩니다. 그러면 우선순위와 오늘 계획도 따라서 바뀝니다.
- **사용자 조정**: 리포트에서 유형별 **초기화**(이전 기록을 빼고 ×1.00부터 다시) 또는 **보정 끄기**를 할 수 있습니다. 과제 하나만 바꾸고 싶으면 예상 시간을 직접 입력하면 됩니다.

#### ⑤ 오늘 계획: 자동 배정 + 직접 수정
1. 오늘 쓸 수 있는 🍅 수 = 오늘 남은 공부 가능 시간 ÷ 30분
2. **1차**: 마감까지 고르게 나눴을 때 "오늘 해야 하는 몫"을 배정합니다. 오늘이 마지막 기회인 과제(오늘 밤 마감 등)가 먼저이고, 그다음 우선순위 순입니다.
3. **2차**: 남는 🍅는 우선순위가 높은 과제에 남은 작업량만큼 더 줍니다.
4. 빈 시간 구간에 실제 시각으로 배치하고, 4회마다 긴 휴식을 넣습니다. 진행 중인 집중이 있으면 그 집중과 휴식이 끝난 뒤부터 배치합니다.
5. 직접 수정한 개수는 고정하고, 나머지만 1~4 방식으로 다시 배정합니다. 오늘 마감인데 모자라면 `부족`, 넣은 개수가 빈 시간보다 많으면 `시간 초과`를 알려 줍니다.

#### ⑥ 토마토 키우기
- 🍅 = 25분 집중을 끝까지 마친 횟수입니다. 중간에 멈추거나 직접 추가한 시간은 🍅로 세지 않습니다.
- 주간 목표 대비 6단계 성장, 단계별 표정과 말풍선, 배지 8종(첫 토마토, 누적 10·50·100개, 3·7일 연속, 하루 8개, 주간 목표), 못 딴 배지의 진행도를 보여 줍니다.

#### ⑦ 그 밖의 편의 기능
- **처음 사용 안내**: ① 일정 등록 → ② 과제 추가 → ③ 첫 🍅 카드. 끝낸 단계는 체크되고, 닫을 수 있습니다.
- **반복 과제**(매주·매월), **완료 되돌리기**, 앱 디자인의 확인창, 하위 작업 그 자리 수정
- **마감 브라우저 알림**: 임박 기준 시점과 1시간 전
- **샘플 데이터**: 불러온 날 기준 날짜라 며칠 뒤에 열어도 지난 과제가 되지 않고, 날짜가 함께 이동합니다.
- **v1 데이터 호환**: 예전 시간표, 직접 입력한 공부 시간, 스톱워치 기록을 자동으로 옮깁니다.
- **디자인**: 빨강(실행·긴급) + 연두(진행·완료·휴식) 두 색만 씁니다(배지 메달만 동색 예외). 다크 모드와 토마토 파비콘을 지원합니다.

### 4-1. duemate-todo-cycle (직접 제작)

**만든 이유**
- 과제 조건 중 지키기 까다로운 것이 세 가지였습니다.
  1. 처음 계획 대비 바뀐 점을 기록할 것
  2. 일정 간격으로 push할 것
  3. 커밋 메시지에 내용을 담을 것
- 셋 다 작업에 몰입하면 "나중에 한꺼번에" 하게 되기 쉬워서, 매 작업의 정해진 단계로 만들었습니다.
- 특히 "Todo 문장은 처음 계획 그대로 두고, 바뀐 점은 변경 내역 표에 따로 적는다"는 규칙 덕분에 3장처럼 계획과 결과를 나란히 비교할 수 있었습니다.

**작업에서 쓰인 방식**
- 피드백을 받을 때마다 `구현 → browser-verify로 검증 → TODO 체크와 변경 내역 한 줄 → 커밋 → push`를 반복했습니다. 그래서 v2 커밋 35개가 모두 기능 단위이고 `type: 한국어 요약 + bullet 본문 + TODO 번호` 형식을 따릅니다.
- 변경 종류(수정·추가·제외·테스트 후 변경)를 정해 둔 덕분에 59건의 변경이 모두 이유와 함께 남았습니다.
- **스킬도 함께 고쳤습니다.** 배포 후 사용자 화면에 새 기능이 안 보이는 문제(브라우저 캐시)를 겪은 뒤 "push 전에 `?v=` 버전 올리기" 규칙을 추가했습니다.

````markdown
# DueMate TODO 사이클

과제 조건은 세 가지다. ① Todo 리스트로 작업하면서 **처음 계획 대비 바뀐 점을 기록**한다. ② 다 만들고 한 번에 올리지 않고 **일정 간격으로 push**한다. ③ 커밋 메시지에 **커밋한 내용**이 드러나야 한다. 이 스킬은 세 조건을 매 작업마다 빠짐없이 지키기 위한 절차다.

## 1. 항목 고르기

1. `docs/TODO.md`의 "v2 Todo 리스트"에서 아직 체크되지 않은 항목을 고른다.
2. 서로 의존하는 항목은 엔진 → UI 순서로 묶는다. (예: B1~B3 계산 엔진 → B4 설정 화면)
3. 한 사이클은 **커밋 1~2개 분량**으로 자른다. 화면 개편처럼 큰 항목은 쪼갠다.

## 2. 구현 규칙

- 빌드 도구 없이 브라우저에서 바로 실행되어야 한다. `<script>` 태그로 불러오는 전역 함수 스타일(기존 `js/*.js`)을 그대로 따른다.
- 새 파일을 만들면 `index.html`과 `tests.html`의 스크립트 순서에 모두 추가한다.
- 계산 로직은 `now` 같은 시간 인자를 받는 순수 함수로 작성해 테스트할 수 있게 한다.
- 저장 데이터 구조를 바꾸면 `store.js`의 `normalize()`에 v1 데이터 변환을 함께 넣는다.
- 화면 문구는 한국어, 이모지는 최소한으로 쓴다.

## 3. 검증

`browser-verify` 스킬로 다음을 확인한다.

1. 모든 `js/*.js`에 `node --check` 통과
2. `tests.html` 헤드리스 실행 결과 실패 0건 (계산 로직을 바꿨다면 테스트를 먼저 추가)
3. 바뀐 화면을 `?demo&tab=...` 스크린샷으로 직접 열어 보고 깨진 곳이 없는지 확인

검증에서 문제가 나오면 고친 뒤, **무엇이 문제였고 어떻게 바꿨는지**를 4단계 변경 내역에 남긴다.

## 4. TODO 갱신

- 끝난 항목은 `- [x]`로 체크한다. 항목 문장은 처음 계획 그대로 둔다. (계획과 결과를 비교하기 위해)
- 계획과 다르게 된 경우 "v2 Todo 변경 내역" 표에 한 줄 추가한다.
  - `| 날짜 | 항목 | 변경 | 이유 |`
  - 변경 종류: **수정**(계획한 기능을 다르게 구현), **추가**(계획에 없던 항목), **제외**(하지 않기로 함), **테스트 후 변경**(검증에서 발견한 문제로 바뀐 것)
- 새로 생긴 항목은 리스트 맨 아래 해당 그룹에 `(추가)` 표시와 함께 넣는다. 뺀 항목은 지우지 않고 `~~취소선~~`과 `(제외)`를 붙인다.

## 5. 커밋과 push

- 메시지 형식: `<type>: <무엇을 했는지 한국어로>` — type은 `feat`, `fix`, `refactor`, `test`, `docs`, `chore`, `style` 중 하나.
- 본문에 바뀐 내용을 2~4줄 bullet로 적는다. 관련 TODO 번호(예: `TODO B1~B3`)를 적는다.
- 코드와 그에 해당하는 TODO 체크는 **같은 커밋**에 넣는다.
- 커밋 2개 이내마다 `git push origin main`으로 올린다. 마지막에 몰아서 push하지 않는다.
- push 후 GitHub Pages 배포 워크플로가 돌기 때문에, push 전 3단계 검증을 반드시 통과시킨다.
- 화면·코드를 바꾼 push 전에는 `index.html`의 `?v=` 버전을 올린다. 브라우저가 css/js를 최대 10분 캐시하므로, 버전을 안 바꾸면 사용자는 새로고침해도 옛 화면을 본다.

## 예시

```

- 활동 시간대에서 고정 일정을 빼고 생활 시간을 제외해 요일별 공부 가능 시간 산출
- 마감 전 가용 시간을 실제 빈 시간 구간으로 계산 (09~24시 균등 가정 제거)
- tests.html에 시간 계산 테스트 8건 추가
TODO B1~B3
```
````

````markdown
# 브라우저 검증

DueMate의 실행 환경은 브라우저로 한정된다. Node에서 돌리는 테스트는 `localStorage`, `document`, 오디오 같은 실제 실행 환경과 다르므로, 테스트와 화면 확인을 **실제 Chrome 엔진**으로 한다. 사람이 브라우저를 열어 클릭하지 않아도 되도록 헤드리스 모드를 쓴다.

## 준비물

- Chrome: 기본 경로 `C:/Program Files/Google/Chrome/Application/chrome.exe` (다르면 `CHROME` 환경변수로 지정)
- Node: `node --check` 문법 검사용
- 앱 쪽 훅
  - `tests.html`: 로드되면 테스트를 실행하고 `<body data-result="pass|fail">`와 `#summary`에 결과를 쓴다.
  - `index.html?demo`: 샘플 데이터를 메모리에만 올리는 데모 모드 (사용자 데이터를 건드리지 않음)
  - `index.html?demo&tab=<탭>`: 특정 탭으로 바로 연다. `&pomo`를 붙이면 뽀모도로가 진행 중인 상태로 연다.
  - `&at=15:00`: 데모의 시계를 그 시각으로 옮긴다. 밤에 찍어도 오늘 계획이 비지 않게 README 스크린샷은 이 값으로 찍는다. `&theme=dark`는 다크 모드, `&form`은 과제 추가 화면.
````

### 4-3. code-review (기존 스킬)

**고른 이유**
- 직접 만든 테스트는 "내가 떠올린 경우"만 검사합니다. 기능을 다 만든 시점에 내가 생각하지 못한 경우를 찾아 줄 외부 시선이 필요했습니다.
- `code-review`는 Claude Code에 기본으로 들어 있는 스킬로, 지정한 변경 범위에서 정확성 버그를 찾아 **"어떤 입력에서 어떻게 틀리는지"**까지 보고합니다. 스타일 지적이 아니라 실패 시나리오 중심이라 목적에 맞았고, 설치 없이 바로 쓸 수 있었습니다.
- 도구에 내장된 스킬이라 저장소에 SKILL.md 파일은 없습니다. 아래는 스킬 설명입니다.

> Review the current diff, or a PR number/branch/path target, for correctness bugs (plus reuse/simplification/efficiency cleanups where the model's recipe covers them) at the effort level given first, before any target (low|medium|high|xhigh|max: from few high-confidence findings to many, some uncertain; ultra: deep multi-agent review in the cloud). Pass --comment to post findings as inline PR comments, or --fix to apply them to the working tree after the review.

**작업에서 쓰인 방식**
- 1차 기능을 모두 만든 뒤 v2 변경 전체를 `medium` 강도로 검토했습니다. 지적 10건을 하나씩 코드로 확인했고 모두 실제 문제였습니다.
- 그중에는 "v1 사용자가 직접 정한 공부 시간이 업그레이드 후 조용히 자동값으로 바뀐다"는 지적이 있었습니다. 기능 버그라기보다 **자동화가 사용자의 결정을 덮어쓰면 안 된다**는 설계 원칙을 일깨워 준 지적이었습니다.
- 9건은 수정하고 회귀 테스트를 붙였습니다. 1건(계산 캐시)은 직접 측정해 보니 21ms여서 넣지 않았습니다.

## 5. 느낀점과 결론

### 5-1. 느낀점

**처음 계획은 16개였지만 끝나고 보니 64개였다.**
- 처음 Todo는 꼼꼼하게 세웠다고 생각했습니다. 그런데 실제로 써 보고 화면을 보면서 생긴 피드백이 계획의 세 배 가까이 늘어났습니다.
- 뽀모도로 위치만 해도 하단 바 → 카드 옆 → 슬라이드 가운데로 세 번 바뀌었습니다.
- 계획을 고치는 것을 실패가 아니라 정보가 늘어난 것으로 보고, 바뀔 때마다 이유를 남겼습니다. 덕분에 지금 이 README에서 "왜 이렇게 됐는지"를 모두 설명할 수 있었습니다.

**자동화의 목표는 '대신 결정하기'가 아니라 '결정을 쉽게 하기'였다.**
- 처음 목표는 사용자의 결정을 대신하는 것이었고, 공부 시간·예상 시간·오늘 계획을 모두 자동으로 계산했습니다.
- 그런데 "결국 본인이 공부하는 거니까 직접 고칠 수 있어야 한다"는 피드백과, 코드 리뷰의 "직접 정한 값을 덮어쓴다"는 지적을 겪으면서 원칙이 바뀌었습니다. **자동 계산은 출발점이고, 최종 결정은 사용자에게 둔다.**
- 그래서 모든 자동 기능에 직접 수정, 되돌리기, 끄기를 함께 두었습니다.

**측정할 수 있는 것과 없는 것을 구분해야 한다.**
- 예상 시간 보정은 실제 작업 시간에 기대는데, 앱은 타이머로 잰 시간만 압니다. 이 한계를 사용자 질문으로 처음 깨달았습니다.
- 그래서 "완료할 때 실제 시간 묻기"와 "직접 기록"으로 보완했습니다. 계산이 정교해도 입력되는 데이터가 틀리면 결과가 틀린다는 것을 배웠습니다.

**검증 방법이 결과물의 질을 정한다.**
- 저장 데이터가 있으면 빈 화면이 되는 버그, 휴대폰에서 타이머가 사라지는 버그, 밤에만 실패하는 테스트는 모두 단위 테스트로는 보이지 않았습니다.
- 이런 문제는 실제 브라우저, 실제 화면, 다른 시간대에서 확인할 때만 드러났습니다. 브라우저 검증을 스킬로 만들어 매번 돌리게 한 것이 가장 효과가 컸습니다.

### 5-2. 방법론 돌아보기: 요구사항 기반 바이브 코딩 + Todo 사이클

이번 작업 흐름은 다음과 같았습니다.
1. PRD와 Todo로 목표를 정합니다.
2. AI가 작은 단위로 구현합니다.
3. 브라우저 테스트와 스크린샷으로 검증합니다.
4. 사용자가 써 보고 피드백합니다.
5. 피드백을 Todo 변경 내역으로 남기고 다시 1로 돌아갑니다.

**장점**
- **속도**: 피드백에서 반영까지 몇 분이면 끝나서, 하루 안에 수십 번 고칠 수 있었습니다. 디자인은 직접 보고 고르는 방식이 가장 효과적이었습니다.
- **추적성**: 스킬로 절차를 고정하니 커밋, Todo, 변경 내역이 항상 함께 갱신되었습니다. 나중에 "언제, 왜 바뀌었는지"를 바로 찾을 수 있습니다.
- **검증 자동화**: 테스트 138건을 매 커밋마다 돌려서, 기능을 계속 바꿔도 이미 되던 기능이 깨지지 않았습니다.
- **외부 시선**: 코드 리뷰 스킬이 내가 생각하지 못한 경우(자정, 숨긴 탭, v1 데이터)를 찾아 주었습니다.

**단점**
- **요구사항이 모호하면 여러 번 왕복합니다.** "뽀모도로를 옆에", "더 예쁘게" 같은 요청은 해석이 여러 가지라, 만들어 보고 다시 고치는 일이 반복되었습니다. 배지 디자인만 다섯 번 바뀌었습니다.
- **부분 최적화가 쌓일 위험이 있습니다.** 피드백마다 그 부분만 고치다 보니, 같은 기능이 다른 탭에 겹치는 일(🍅 통계가 리포트와 성과 탭 양쪽에)이 생겨 나중에 따로 정리해야 했습니다.
- **AI가 놓치는 영역이 있습니다.** 실제 기기의 알림음, 휴대폰 터치감, 브라우저 캐시처럼 헤드리스 환경에서 확인할 수 없는 부분은 사람이 직접 써 봐야만 알 수 있었습니다.
- **테스트도 틀릴 수 있습니다.** 실행 시각에 따라 실패하는 테스트, 잘못된 기댓값처럼 테스트 자체의 버그를 고치는 데에도 시간이 들었습니다.

**개선이 필요한 점**
- **디자인 요청은 시안을 먼저 보여 주기**: 구현 전에 2~3개 안을 그림으로 보여 주고 고르게 하면 왕복이 줄어듭니다. 탭 구성은 이 방식으로 한 번에 정해졌습니다.
- **주기적으로 전체 점검하기**: 피드백 몇 개마다 "겹치는 기능, 흩어진 설정"을 전체적으로 보는 단계를 사이클에 넣어야 합니다.
- **실제 기기 테스트 체크리스트**: 알림음, 휴대폰 실기기, 배포 후 캐시처럼 자동화가 못 보는 항목을 따로 확인합니다.
- **실제 사용자 데이터로 검증하기**: 예상 시간 기본값과 보정 방식은 제가 정한 출발값입니다. 실제 대학생 여러 명의 기록으로 다듬어야 합니다.

### 5-3. 결론

DueMate v2는 "무엇부터 할지"라는 결정을 쉽게 만드는 데 집중했습니다.
- **입력은 줄였습니다.** 일정만 넣으면 공부 시간이, 유형만 고르면 예상 시간이 계산됩니다.
- **실행은 한 번에 합니다.** 지금 할 일과 타이머가 첫 화면 가운데에 있습니다.
- **쓸수록 정확해집니다.** 실제 작업 시간이 예상 보정과 다음 계획에 반영됩니다.
- **꾸준함에는 보상이 있습니다.** 모은 🍅로 토마토가 자라고 배지가 생깁니다.

자동으로 계산하되 언제든 직접 고칠 수 있게 한 것이 v1과 가장 큰 차이입니다.
