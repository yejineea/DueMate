## 1. 프로젝트 개요
- 프로젝트 이름: DueMate
- 한 줄 소개: 할 일이 많은 대학생 대신 "지금 무엇부터 할지"를 정해 주고, 뽀모도로로 바로 집중하게 해 주는 과제·일정 관리 웹 앱
- 만드는 사람: yejineea
- 완성 목표일: 과제 제출 전까지 (v1 완성 후 v2 개선)

## 2. 왜 만드나요? (목적)
- 여러 과목의 마감이 겹칠 때 무엇부터 해야 할지 판단하기 어렵다.
- 과제 개수만으로는 실제 부담을 알 수 없다.
- 수업·아르바이트 때문에 쓸 수 있는 공부 시간이 제한적이다.

v1을 써 보니 드러난 문제 (v2에서 해결):

| 문제 | v2 해결 |
| --- | --- |
| 첫 화면이 산만해 "지금 할 일"이 눈에 띄지 않음 | 뽀모도로 탭: 지금 할 일 슬라이드 + 타이머 + 오늘 계획만 |
| 공부 가능 시간·예상 소요 시간을 매번 직접 입력 | 일정으로 공부 가능 시간 자동 계산, 유형·난이도로 예상 시간 자동 추정 |
| 추천을 받아도 실행으로 이어지지 않음 | 과제별 뽀모도로 타이머, 집중 시간 자동 기록 |
| 계속 쓰게 만드는 동기가 없음 | 토마토 키우기(주간 목표·성장 단계·배지) |

## 3. 누가 사용하나요? (사용자)
- 주 사용자: 여러 과목의 과제와 시험을 병행하며, 수업·아르바이트 사이 제한된 시간 안에서 계획을 세워야 하는 대학생
- 사용 환경: 주로 노트북 브라우저, 이동 중에는 스마트폰
- 사용자에 대해 알아야 할 점: 시험 기간에 할 일이 몰리고, 계획을 세우는 데 드는 입력과 고민 자체를 번거로워한다

## 3-1. 대표 사용자 페르소나
- 이름/나이: 김민지 / 21세, 컴퓨터공학과 2학년
- 상황: 자료구조·웹프로그래밍·경영학원론·영어회화·통계학 수업에 주 3회 카페 아르바이트를 한다. 중간고사 기간에 과제와 시험이 한꺼번에 몰려 매일 저녁 "오늘 뭐부터 하지?"를 고민한다.
- 바라는 것: 앱을 열면 지금 할 일과 오늘 몇 시에 무엇을 할지가 바로 보이고, 버튼 하나로 집중을 시작하는 것
- 불편해하는 것: 공부 가능 시간·예상 시간 같은 숫자를 매번 직접 입력하는 것, 정보가 너무 많아 산만한 화면

## 4. 꼭 있어야 하는 기능 (핵심 기능)
1. 사용자는 앱을 열자마자 우선순위와 남은 빈 시간을 바탕으로 정해진 "지금 할 일"과 시간대별 오늘의 🍅 계획을 볼 수 있고, 필요하면 직접 고칠 수 있다.
2. 사용자는 수업·알바 일정만 등록하면 요일별 공부 가능 시간을 자동으로 받을 수 있다. (원하면 직접 입력도 가능)
3. 사용자는 과제를 등록할 때 예상 소요 시간을 직접 넣지 않아도 되며, 실제 작업 시간이 쌓일수록 예상이 자기 속도에 맞춰진다.
4. 사용자는 과제별 뽀모도로 타이머로 바로 집중하고, 집중 시간이 과제에 자동으로 기록된다.
5. 사용자는 모은 🍅로 토마토를 키우고 배지를 모으며 꾸준함을 확인할 수 있다.
6. (그 밖에 필요한 기능) 사용자는 과제·단계·반복 과제를 관리하고(To Do·캘린더), 작업량·예상 정확도·성적을 확인하며(리포트), 알림·테마·백업을 설정할 수 있다.

## 5. 만들지 않는 것 (범위 제외)
- 회원가입/로그인은 만들지 않는다.
- 서버 동기화(기기 간 자동 동기화)는 만들지 않는다. 다른 기기에서는 JSON 백업·복원으로 옮긴다.
- 여러 사람이 함께 쓰는 공동 작업 기능은 만들지 않는다.

## 6. 모양과 분위기 (디자인)
- 원하는 느낌: 군더더기 없이 필요한 기능이 앞에 오는 깔끔한 화면, 토마토 컨셉의 귀여운 재미 요소
- 주요 색상: 빨강(토마토 · 실행·긴급) + 연두(진행·완료·휴식) 두 색. 배지 메달만 주황~갈색(동메달) 예외. 그래프는 채도를 낮춤
- 참고하고 싶은 사이트나 이미지: 뽀모도로(토마토) 타이머, 원형 타이머

## 7. 기술 조건
- 결과물 형태: 웹앱 (탭 5개: 뽀모도로 · To Do · 리포트 · 토마토 키우기 · 설정)
- 사용할 도구나 언어: HTML·CSS·JavaScript, 빌드 도구 없음, GitHub Pages 배포
- 지켜야 할 조건:
  - 실행 환경은 브라우저로 한정, 서버 없이 `localStorage`에 저장
  - `index.html`을 열거나 GitHub Pages에서 바로 실행
  - 데스크톱과 휴대폰(390px) 화면, 라이트·다크 테마 지원
  - v1 데이터(localStorage, JSON 백업)를 v2에서 그대로 불러옴
  - 핵심 계산과 화면 조작은 브라우저 테스트 페이지(`tests.html`)로 검증

## 8. 가정한 것들
- 사용자는 주로 한 브라우저(기기)에서 사용한다고 가정
- 사용자는 한국어 사용자라고 가정
- 25분 집중 + 5분 휴식(뽀모도로)이 기본 공부 단위로 적합하다고 가정
- 하루의 공부 가능 시간은 그날의 빈 시간 구간에 고르게 퍼져 있다고 가정
- 수업·알바는 대부분 매주 반복되는 일정이라고 가정
- 유형별 기본 시간(보고서 3h·발표 4h·코딩 5h·시험 공부 6h·시험 8h·기타 2h)은 출발값이며, 실제 기록으로 보정된다고 가정

## 9. 결정하거나 조사해야 할 것 (열린 질문)
- 유형별 기본 시간과 보정 방식은 실제 대학생 여러 명의 기록으로 검증이 필요하다.
- 탭을 닫아도 마감 알림을 받으려면 PWA(설치형 앱)로 만들어야 할까?
- 기기 간 동기화가 필요할 만큼 여러 기기에서 쓰는 사용자가 많을까?
- 오늘 계획 슬롯을 캘린더 주간 보기에 함께 보여 줄까?

## 10. 완성 기준 (이러면 성공!)
- 앱을 열면 스크롤 없이 지금 할 일·타이머·오늘 계획이 보인다.
- 일정만 등록하면 공부 가능 시간이 계산되고, 계산 근거를 표로 확인할 수 있다.
- 과제 입력 시 예상 시간을 직접 넣지 않아도 되고, 완료 기록이 쌓일수록 예상이 내 속도에 맞춰진다.
- 한 번의 클릭으로 뽀모도로를 시작하고, 집중 시간이 과제에 기록된다.
- v1 데이터가 유지되고 테스트 페이지의 모든 테스트가 통과한다.
